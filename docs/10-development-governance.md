# Kernel-first 开发治理

本文件是功能进入、复杂度和扩展边界的合并门禁。超过硬上限时停止实现，先拆分里程碑或由用户明确
批准新的预算。

## 1. 决策优先级

1. 产品章程：产品是谁、主线是什么。
2. Kernel 架构与 accepted ADR：稳定边界和依赖方向。
3. 当前里程碑 scope/acceptance：本轮唯一故事。
4. 代码与测试：当前真实行为。

未来路线图不授权当前实现。当前里程碑没有真实调用路径的能力不能进入产品源码。

## 2. 里程碑文档包

从下一个功能里程碑开始最多使用五份文档：

```text
docs/plans/<milestone>/
  00-scope.md       # 唯一用户故事、场景、边界
  01-design.md      # 数据流、contract、失败语义
  02-tasks.md       # 可测试任务与实时状态
  03-acceptance.md  # 命令和退出标准
  04-closeout.md    # 实际交付、预算和下一输入
```

设计文档只描述本里程碑实际交付的类型和事件。未来扩展只记录接入 seam，不预定义其内部 schema。

## 3. 功能准入门

开始编码前全部为“是”：

- [ ] 能用一句话描述本里程碑唯一用户故事。
- [ ] 功能服务该故事或保护已经存在的副作用。
- [ ] 本轮结束时存在 CLI/Application 真实调用路径。
- [ ] 已找到可复用的最小闭合实现。
- [ ] 已指定一个 Kernel seam；若新增 seam，说明当前调用方。
- [ ] 正常路径和最重要失败路径可以自动验收。
- [ ] 预计规模在硬预算内。

任一项为“否”，功能留在路线图，不进入任务列表。

## 4. 硬复杂度预算

| 指标 | 默认预算 | 硬上限/动作 |
| --- | --- | --- |
| 单里程碑新增产品源码 | ≤ 1,000 行 | 超过时拆分；调整需用户批准 |
| 单里程碑新增产品模块 | ≤ 6 个 | 第 7 个前进行职责复查 |
| 单里程碑新增领域概念 | ≤ 3 个 | 超过时拆分用户故事 |
| 里程碑文档 | ≤ 5 份 | 合并场景和状态记录 |
| AgentLoop | ≤ 500 行 | 超过前先提取已命名能力 |
| 普通产品模块 | ≤ 300 行 | 超过前确认是否承担多个责任 |
| Agent Kernel 总量 | ≤ 2,000 行 | 超过时停止扩展并收口 |
| v0.1.0 产品源码总量 | ≤ 8,000 行 | 6,000 行触发全局范围复查 |
| 当前里程碑 durable event | ≤ 7 类 | 每类必须有 producer 和 reducer |
| 新 runtime dependency | 默认 0 | 需要 accepted ADR 和用户批准 |

Kernel 统计范围：`agent/`、`protocol/`、`runtime/`、`tools/base.py`、`tools/registry.py`、
`app/application.py`、`app/factory.py`。

行数是停止信号，不以机械拆文件规避；拆分必须产生可以独立命名和测试的能力。

## 5. 抽象与插件规则

- Protocol 只用于 Kernel seam，或已有两个可替换实现的边界。
- 新 Protocol 默认不超过 5 个方法。
- 新扩展通过 Registry/factory/preset 注册。
- 扩展依赖公开 DTO/Protocol，不导入 AgentLoop 私有实现。
- AgentLoop 不导入具体 Provider、Tool 或 UI。
- 只有 composition root 选择实现。
- 一个调用方的便利函数直接放在调用方附近，不创建转发 facade。
- 每个公开类型、配置项和事件在同一里程碑必须有 producer 与 consumer。

首版可插拔性由显式 Python composition 提供；package discovery 在 M8 作为独立用户故事实现。

## 6. 复用优先流程

```text
冻结用户演示
  -> 定位参考项目最小实现
  -> 读取其依赖和测试
  -> 迁移闭合骨架
  -> 统一本项目 contracts
  -> 只增加本项目差异点
  -> 删除未接线的迁移残留
```

复用目标是减少概念和代码，不以迁移完整子系统为目标。

## 7. 实现节奏

1. 先写一个能运行失败的纵向测试。
2. 实现通过主路径所需的最少代码。
3. 加入唯一关键失败/安全测试。
4. 运行全量回归。
5. 执行自动架构门禁。
6. 由新读者视角沿主 Trace 检查跳转数量和命名。
7. Closeout 记录实际行数、模块、概念和依赖。

## 8. Stop-the-line 条件

出现任一情况立即暂停当前功能：

- 需要第二个 Agent Loop 或恢复专用循环；
- 状态同时由两个持久化来源写入；
- 扩展需要读取 AgentLoop 私有字段；
- 新增代码超过预算仍无法完成唯一演示；
- 为未来版本创建当前无调用路径的包、事件或配置；
- 测试主要验证内部 mock，而没有验证用户入口或真实副作用；
- 一项能力需要同时引入两个状态机。

暂停后只允许缩小 scope、复用现有实现或拆分里程碑。

## 9. Closeout 必填证据

- 唯一用户故事和演示命令；
- 新增产品源码行数、模块数、领域概念数；
- AgentLoop、Kernel 和全项目源码行数；
- 新增 contracts/events/dependencies 及其 producer/consumer；
- 主路径、关键失败和回归测试结果；
- 新 Tool/Provider 是否保持 AgentLoop 零修改；
- 下一里程碑只记录输入，不提前创建实现类型。
